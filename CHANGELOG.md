# Changelog

All notable changes to `execution-service` are documented in this file.

Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Fixed

- Connector worker dispatch: a stream entry the worker cannot read (a bad tenant, task or department id, an all-zero department id, or inputs that are not a JSON object) is moved to the dead-letter stream with reason `malformed_entry` and counted in the dead-letter metric and alert, and its task stays open; it used to be acknowledged and dropped with one error log line. A full connector pool for one type no longer delays other types' entries: up to one extra pool's worth of that type's entries waits, beyond that the worker waits for that type again, and a shutdown ends the wait at once; the whole read loop used to block. A redelivered entry whose connector outcome is already recorded resends that outcome even past the delivery cap; it used to be dead-lettered although the work was done. A lost consumer group (for example after a Valkey flush) is recreated and dispatch resumes without a restart; the worker used to log a read failure every second until restarted.
- Connector streams: the worker trims the task stream up to its oldest unacknowledged entry and drops dead-letter entries older than `CONNECTOR_STREAM_DEAD_LETTER_RETENTION` (default `720h`, chart value `connectorWorker.deadLetterRetention`); neither stream was ever trimmed. When copying an entry to the dead-letter stream fails, the entry stays pending and is retried; it used to be acknowledged anyway and lost without a copy.
- The processed-events prune deletes in batches of `RETENTION_SWEEP_BATCH`, and one consumer failing no longer skips the others, whose deleted rows are still counted; it used a fixed 5000 and stopped at the first failing consumer.
- A 5xx answer from OpenBao no longer puts the upstream response body into the connector worker's error; the error names the path, field and status only.
- Configuration: a zero or negative timeout, refresh interval, retention, Valkey timeout, idempotency TTL or connector pool size stops startup with an error naming the variable; these used to start and then delete every audit row, expire every call at once or remove the time limit. `OTEL_TRACES_SAMPLER_RATIO=NaN`, two equal listen ports, a negative `CONNECTOR_STREAM_BLOCK_TIMEOUT` and a `CONNECTOR_STREAM_BATCH_SIZE` below 1 are refused at startup. A `START_REFUSED_STATUSES` holding only separators takes the default list instead of switching the tenant-status guard off. A `.env` file that exists but cannot be parsed stops startup naming the file; the error used to be dropped.
- The API refuses to start without a valid `TOKEN_SERVICE_BASE_URL` (an http or https URL), in every environment; an empty address used to answer `409 NO_AUTOMATION_PRINCIPAL` on every connector callback and a malformed one `500`. The chart now always requires `env.tokenServiceBaseURL`.
- A connector worker that cannot read its host name reads the stream as `connector-worker-<random suffix>`; every such pod used to share the name `connector-worker`.

- The membership-revocation pause (`POST /api/v1/internal/users/{user_id}/pause-tasks`) attempts every instance and answers `503` when it could not read a task or an instance or could not signal one, so the Definition Service retries; it used to log a Warn and answer `204`. `workflow_execution_service_user_pause_failures_total{stage}` counts each failure.
- The connector worker's callback error and log line carry the status and the first 200 bytes of the answer; the chart gains a `ConnectorDispatchDeadLettered` alert and a PodMonitor for the connector worker.
- The connector worker skips an alias row the connector library refuses (logged by alias) instead of failing to start, keeps the previous registry when a refresh yields no usable alias, caps the registry answer at 1 MiB, and reports `workflow_execution_service_connector_alias_registry_age_seconds`.

- The task queue choice at instance start keeps the registry in agreement with the grant: a grant that reads false also stops the tenant queue routing, a granted tenant whose queue is not registered yet starts on the plan queue and registers it for the next start (workers find new queues only on their topology interval), and a registered routable queue is used without a write on every start.

- The `503` body for an unavailable upstream carries a fixed detail instead of the Go error text (host, port, path); the cause stays in the log. An event type the service does not handle is labelled `unknown` in the ingest and last-received metrics. The row-level-security tenant setting of the event handlers is built from the parsed tenant id.

- A refused internal event (no timestamp, a schema payload that cannot be decoded) is counted under the `unknown` event type too; the type is request text until the type check has run.

- The Entitlements grant cache serves a set past its TTL while a background read renews it only up to twice the entry's TTL (and never past the freshness bound). An older set makes the caller wait for the read and falls back to the held set, counted as a stale serve, only if the read fails inside the freshness bound. It used to serve the held set for the whole bound, so a revocation could stay visible for up to ten minutes after an idle period.

- Tests only: the connector worker gains tests for startup (a failed first alias fetch, the stream consumer name, the version flag and config errors), alias refresh, dispatch and reclaim, heartbeats, callback redelivery, the health server and shutdown order; the Valkey stream consumer and publisher, the event inbox and its prune, the OpenBao reader, the Definition and automation-principal clients and the slow-query log gain edge-case tests.

- Tests only: the Temporal worker gains tests for startup and registration, the queue-topology poller, health and readiness, and its exit paths (run as a built binary); the activities gain tests for tenant scope, instance nodes, event arrays, cancel and defer, and lifecycle versions; the workflow gains tests for activity retry policy, boundary timers, degraded status writes, exclusive gateways, external answers, force-back node writes, older histories and sub-workflows; the alert tests cover `WorkerQueuePollingStalled` and `InstancesOnUnpolledQueue`. The architecture check exempts `cmd/worker`'s integration-tagged tests from the fixtures import rule, as it already does for the connector worker's end-to-end tests.

- Tests only: a chart test reads the internal routes from the router (the internal group and the groups below it) and fails when one belongs to no `authorizationPolicy.internalRoutes` group or to more than one, so a new internal route is not left closed without notice.

- The connector worker applies an empty alias registry answer after three in a row (the first two are held back with a Warn, as before), so deleting the last alias reaches running workers. A non-empty answer or a failed fetch starts the count again.

- The connector worker's log line for a skipped alias row names the alias and the part of the row that failed (base URL, path, method, duplicate) and no longer carries the connector library's error text, which quoted the whole base URL with its userinfo.

- The membership-revocation pause treats an instance whose workflow is already gone (Temporal answers not found) as paused: it is not counted as a pause failure and no longer makes the batch answer `503`, so a retry loop ends once only real failures are left.

- Outbound clients that forward the system caller identity or a secret (Entitlements, Definition, token service, eligibility, OpenBao, the connector worker's completion callback and alias fetch) return a redirect as the answer instead of following it.

- A request refused by the internal-route caller check is counted in `workflow_execution_service_internal_auth_rejected_total{reason}` (`missing_user` or `missing_role`). The caller identity `iam-system` is one constant (`domain.SystemCaller`) used by the check and by every sender.

### Changed

- Contract copies: a copy in `api/contracts/` that differs from its source no longer fails `make contract-check` unless the source has a breaking change (oasdiff) on a route this service calls (the compiled-plan read and the alias list, a fifth column in `api/contracts/SOURCES`). The copy of the Definition Service's internal spec is refreshed from its corrected version. LLD copy 1.154.
- CI: a change that touches only documentation (Markdown, Mermaid, `.claude/`, `docs/` except `docs/swagger/`, `LICENSE`) runs the CI gate and reports the required checks as skipped, not pending; the workflow no longer uses `paths-ignore`. No job or check name changes.
- CI: the `sqlc` binary and, in the test and quality jobs, the `.tools` directory are cached by the Makefile hash, so a job no longer compiles them on every run. `make test-ci` runs the unit and integration suites at the same time, then merges their coverage. No job, dependency or check name changes.
- LLD copy 1.153: every browser-originated route requires `x-tenant-id` and `x-user-id`, administrative routes check `x-tenant-roles`, and task and instance reads use `x-departments`; `x-plan` and `x-feature-flags` are not read. The earlier text listed all six headers as validated.
- The connector worker no longer sends an `x-internal-token` to connector alias targets. `workflow-connectors` v2.4.0 makes the token optional, so the worker builds the connectors without one; the placeholder text `unset`, its startup Info line and the `CONNECTOR_ALIAS_CALL_TOKEN` setting (configuration, chart values, connector worker Deployment) are removed. The caller identity headers are sent as before.
- Contract copies: `make contract-check` no longer reads a branch name from `api/contracts/SOURCES` (its branch column is gone). It compares the copy with the Definition Service's branch named like the branch under test when that branch exists, and with `main` otherwise, the rule the compat job already uses; `CONTRACT_SRC_REF` overrides it. `make contract-check-test` tests the script and runs in `make check`.
- Docs only: the in-repo LLD, the internal OpenAPI and the copy of the Definition internal spec match the design repository again. No code changed.
- Docs only: the in-repo LLD is brought to 1.151 and the internal OpenAPI states that a pause signal that finds the workflow already gone counts as paused (the stale window of the flag cache ends at twice the TTL, the alias registry applies the third empty answer in a row, and the ingest metric labels refusals before the type check `unknown`). No code changed.
- Chart: fixed names (`fullnameOverride: workflow-execution-service`), per-path caller rules (`authorizationPolicy.internalRoutes` replaces `internalCallers`: events, Definition calls, Org & Membership routes, connector-task callbacks), the NetworkPolicy admits the connector worker and Org & Membership, the render refuses a disabled policy in staging and prod unless `authorizationPolicy.allowDisabled`, `appProtocol: http` on the metrics ports, the Entitlements egress rule needs ports and pods, and the chart tests decode the rendered rules.

Status codes are unchanged; the `401` detail is `missing or invalid internal caller identity`. The optional `CONNECTOR_ALIAS_CALL_TOKEN` is sent as `x-internal-token` on calls to alias targets only, because `workflow-connectors` v2 refuses an empty token; when it is unset the worker sends the text `unset` and logs one Info line at startup.
- `POST /api/v1/internal/users/{user_id}/pause-tasks` takes an optional `department_id` (UUID; absent or null means every department): only the instances holding the user's task in that department are paused, so a department-membership revocation no longer pauses the user's work elsewhere; a malformed or all-zero id answers `400 BAD_REQUEST` (LLD revision 1.145).

Neither depends on a branch that gets deleted any more.

### Fixed

- A paused instance lost its pause when a parallel branch failed: the instance became `DEGRADED` and left the park `RUNNING`, and `instance-pause` and `instance-resume` were dropped while degraded, so a suspended tenant's instance ran again after an administrator's force-forward and a suspension during the park was never applied. A pause in force when a branch fails is carried into the park, a pause or resume received during it is recorded with its initiator under the existing ownership rule, and the park ends `PAUSED` when a pause is held and `RUNNING` otherwise (change ID `pause-survives-degraded`; a history recorded before it keeps the old behaviour).
